# Engineer Instruction: TripDataHub Docs Phase 0

## Purpose

TripDataHub has grown beyond what chat history and ad hoc comments can safely hold. We need a small, durable documentation layer that future AI agents and engineers can read before changing CloudKit, timeline rendering, bid periods, timezone logic, or schedule model ownership.

This is **Phase 0**. Keep it small. Do not create the full 30+ file structure yet.

## Goals

- Reduce context drift between Codex, Claude, and future agents.
- Make domain invariants explicit.
- Prevent repeated architecture debates.
- Document CloudKit record ownership and schema assumptions.
- Clarify schedule terminology that has repeatedly caused bugs.
- Keep docs useful enough that engineers will actually maintain them.

## Directory Convention

Use lowercase:

```text
docs/
```

Do **not** create `Docs/`. The repo already has `docs/`.

## File Requirements

### 1. `docs/AI_CONTEXT_INDEX.md`

This is the routing layer for future AI sessions.

It should be short, roughly 30-60 lines.

Include:

- Purpose of this docs layer.
- Trigger-based reading instructions, not a huge "always read" list.
- Workflow rules before implementation and before commit.
- Conflict rule: if code and docs disagree, stop and report.

### 2. `docs/INVARIANTS.md`

This file contains rules that must not silently change.

Include at least:

- UTC is source of truth for internal calculations.
- Local time is for rendering and domain boundary interpretation.
- Timezone conversion must be explicit.
- BP/PP membership is based on departure time crossing 03:00 LDT boundary for the user's domicile.
- Domicile controls LDT.
- Timeline and Friends timeline should use the same row/card rendering components when possible.
- CrewAccess import JSON is the recoverable source for file-based import state.
- CloudKit sync must avoid stale remote rollback of newer local state.
- Deletions that cross devices should use tombstones or equivalent conflict-safe semantics where needed.

Keep each invariant numbered:

```md
INV-001: UTC Source Of Truth
...
```

### 4. `docs/CLOUDKIT.md`

Document current CloudKit schema and ownership expectations.

For each record type, include:

- Record Type
- Purpose
- Record name pattern
- Key fields
- Owner/user model
- Tombstone behavior
- Security role expectation
- Production deploy requirement when changed

Record types to document:

- `TDHGEMSVerification`
- `TDHVerifiedUser`
- `TDHFriendLink`
- `TDHSharedSchedule`
- `TripScheduleSnapshot`
- `TDHDeviceScheduleSnapshot`
- `TDHCrewAccessImportFile`

Include Security Role baseline:

```md
Public DB:
- `_icloud`: Create / Read / Write where users need to create or update their own sync records.
- `_creator`: Read / Write where applicable.
- `_world`: generally no write; read only when intentionally public.
```

Also include:

- Development schema must be generated by running a Development build once.
- After schema/field/index changes, deploy schema changes to Production before TestFlight/App Store use.
- Query fields must be marked Queryable before code relies on CloudKit queries.

### 5. `docs/BID_PERIODS.md`

This is a core domain document.

Must include:

- PP and BP definitions.
- PP starts at 03:00 LDT on start date.
- PP ends at 02:59 LDT on the day after the listed end date boundary, or equivalently before the next PP 03:00 LDT boundary.
- BP consists of paired PP periods except special 4-week BP cases.
- Membership is determined by **departure time** crossing the 03:00 LDT boundary.
- Domicile determines LDT.

Current domiciles:

```text
ANC  -> Anchorage time
SDF  -> Louisville time
SDFZ -> Louisville time
ONT  -> Ontario/Los Angeles time
MIA  -> Miami/New York time
```

Include the known PP/BP mapping currently in code for 2025-2027, or explicitly reference the code source if copying the whole table would be too noisy. The document must still include the key examples:

- `PP26-06`: 2026-05-17 03:00 ANC starts, 2026-06-14 02:59 ANC ends.
- `PP26-07`: 2026-06-14 03:00 ANC starts, 2026-07-12 02:59 ANC ends.
- `BP26-04`: PP26-06 + PP26-07, from 2026-05-17 03:00 ANC through 2026-07-12 02:59 ANC.
- `BP26-07`: special 4-week Bid Period.

Also note:

- SDFZ uses SDF/Louisville LDT.
- Future bases must be added through `DomicileSupport` and tests.

### 7. `docs/ADR/ADR-002-utc-source-of-truth.md`

Record the UTC-first decision.

Include:

- Status: Accepted
- Internal calculations use UTC.
- Local time is used for rendering and LDT domain boundaries.
- Tests should protect timezone/DST/date-line behavior.
- Any move away from this requires a new ADR.

### 8. `docs/ADR/ADR-003-crewaccess-file-cloudkit-sync.md`

Record the decision to sync CrewAccess import JSON files through CloudKit, not only derived Timeline schedules.

Include:

- Status: Accepted
- Context: iOS/iPad can import randomly; Timeline was syncing but Settings file state diverged.
- Decision: sync recoverable CrewAccess import JSON files via `TDHCrewAccessImportFile`.
- Consequences:
  - Settings `CrewAccess Imports (Files)` can converge across devices.
  - Timeline can be rebuilt from restored import files.
  - Deletions need tombstone semantics.
  - File identity must be stable enough to avoid duplicates across devices.
- Related code areas:
  - `CrewAccessImportCloudKitService`
  - `AppViewModel.fetchCrewAccessImportFilesIfNeeded`
  - `AppViewModel.listCrewAccessImportFiles`
  - `AppViewModel.deleteCrewAccessImportFiles`

## Process Rules To Include

Add these rules either in `AI_CONTEXT_INDEX.md` or a short section inside relevant docs:

### Before touching CloudKit

- Read `docs/CLOUDKIT.md`.
- Confirm record type and field names.
- Confirm whether new fields require Development schema creation and Production deploy.
- Confirm query fields have Queryable indexes if used in predicates.
- Add/update service tests where possible.

### Before touching Time / Calendar / Timeline

- Read `docs/INVARIANTS.md` and `docs/BID_PERIODS.md`.
- Add or update tests for DST, timezone crossing, UTC date boundary, and LDT 03:00 boundary when affected.

### Before touching schedule arrays

- Read `docs/TERMINOLOGY.md`.
- Explicitly decide whether the change affects:
  - source import files
  - CrewAccess parsed schedules
  - merged display schedules
  - CloudKit device snapshots

## Non-Goals For Phase 0

Do not:

- Build the full `Architecture/`, `Rendering/`, `EdgeCases/`, `Testing/` hierarchy yet.
- Move large chunks of `AGENTS.md` or `CLAUDE.md` in this pass unless necessary.
- Rewrite code solely to match docs.
- Create empty placeholder files.

## Validation

After creating docs:

1. Confirm all links/paths are correct.
2. Run `rg "Docs/"` and ensure no new uppercase `Docs/` references were introduced.
3. Run `rg "docs/" docs AGENTS.md CLAUDE.md README.md` to confirm references are consistent.
4. No app build is required unless code or project files are changed.
